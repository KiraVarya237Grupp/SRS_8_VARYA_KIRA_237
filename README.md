# МедиаТрекер — Система учёта личной библиотеки и трекинга медиаконтента

## 1. Назначение
Веб-приложение **«МедиаТрекер»** предназначено для ведения персонального каталога медиаконтента (фильмов, сериалов, книг, игр), учёта имеющихся у пользователя форматов носителей (бумажных, цифровых, аудио), контроля этапов просмотра/чтения и автоматического ведения истории активности.

## 2. Функциональность
* **Каталогизация личной коллекции:** ведение справочника произведений (`Title`), жанров (`Genre`) и форматов носителей в коллекции (`FormatInstance` — Бумажная книга, Цифровая версия, Аудио и др.).
* **Контроль состояний (State Machine):** последовательные переходы статусов по маршруту `planned` (В планах) -> `in_progress` (Читаю / Смотрю сейчас) -> `completed` (Прочитано / Завершено) на основе правил `ALLOWED_TRANSITIONS`.
* **Транзакционность и целостность данных:**
  * Все изменения статуса карточки и запись в журнал истории выполняются атомарно внутри блока `transaction.atomic()`.
  * Демонстрационный режим проверки отказоустойчивости (кнопка «Сбой») с автоматическим откатом транзакции (`Rollback`) при возникновении ошибки.
* **Журнал истории библиотеки (Аудит):** автоматическая фиксация каждого события (`created`, `status_changed`, `updated`) в модели `EntryEvent` с сохранением времени `timestamp` и описания изменения.
* **Разграничение профилей:** привязка записей к владельцу (`owner`) с возможностью переключения между основным и дополнительным профилем в интерфейсе.
* **Динамический интерфейс (REST API):** быстрая фильтрация по жанрам и статусам, живой поиск по названию и экспресс-кнопки смены статусов через `Fetch API` без перезагрузки страницы.
## 3. Технологии
* **Backend:** Python 3.11+, Django 5.x, Django REST Framework (DRF)
* **Frontend:** HTML5, CSS3, JavaScript (Fetch API)
* **База данных:** SQLite 3 (локально), PostgreSQL (облачное развёртывание)
* **Инфраструктура:** Gunicorn, WhiteNoise, `dj-database-url`, `python-dotenv`

## 4. Подготовка окружения
Требуется **Python 3.10 — 3.12**.

```bash
# 1. Клонирование репозитория и переход в папку проекта
git clone <ссылка_на_репозиторий>
cd PythonProject5

# 2. Создание и активация виртуального окружения
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# 3. Установка зависимостей
pip install -r requirements.txt
```

## 5. Настройка
Скопируйте шаблон `.env.example` в файл `.env`:
```bash
copy .env.example .env
```
Переменные окружения в `.env`:
* `DJANGO_SECRET_KEY` — секретный ключ Django (`django-insecure-change-me-example-key-12345`).
* `DJANGO_DEBUG` — режим отладки (`True` для локального запуска).
* `DJANGO_ALLOWED_HOSTS` — разрешённые хосты (`127.0.0.1,localhost`).
* `DJANGO_CSRF_TRUSTED_ORIGINS` — доверенные источники CSRF (`http://127.0.0.1:8000,http://localhost:8000`).
* `DATABASE_URL` — подключение к БД (`sqlite:///db.sqlite3`).

## 6. Запуск
```bash
# 1. Применение миграций базы данных
python manage.py migrate

# 2. Сборка статических файлов
python manage.py collectstatic --noinput

# 3. Создание администратора (если ещё не создан)
python manage.py createsuperuser

# 4. Запуск локального сервера
python manage.py runserver
```
Адреса страниц после запуска:
* **Интерфейс каталога:** `http://127.0.0.1:8000/catalog/`
* **Панель администратора:** `http://127.0.0.1:8000/admin/`

## 7. Проверка работоспособности
1. Откройте `http://127.0.0.1:8000/catalog/` — убедитесь, что загрузились карточки произведений и кнопки фильтрации.
2. Откройте консоль браузера (**F12 -> Network -> Fetch/XHR**).
3. Нажмите кнопку смены статуса на карточке (например, «Начать» или «Сразу готов») — проверьте ответ `200 OK` в Network и обновление карточки.
4. Нажмите кнопку «Сбой» — убедитесь, что выводится сообщение об откате транзакции, а данные в БД остаются целостными.
5. В панели `/admin/catalog/entryevent/` проверьте появление новых записей в «Истории библиотеки».
